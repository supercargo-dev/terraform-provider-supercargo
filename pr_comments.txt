For token sources that return a token without an expiration time (e.g., static or mock tokens), `token.Expiry` is initialized to the zero value (`time.Time{}`). In Go, `time.Until(time.Time{})` returns a large negative duration, which is always less than `time.Minute`. This causes the credentials helper to proactively refresh the token on every single gRPC request, completely bypassing the cache and causing severe performance degradation and potential rate-limiting. Checking `!token.Expiry.IsZero()` before comparing the duration prevents this issue.

```suggestion
	if token == nil || (!token.Expiry.IsZero() && time.Until(token.Expiry) < time.Minute) {
		c.mu.Lock()
		defer c.mu.Unlock()

		// Re-check after acquiring write lock
		if c.token == nil || (!c.token.Expiry.IsZero() && time.Until(c.token.Expiry) < time.Minute) {
			newToken, err := c.source.Token()
			if err != nil {
				return nil, fmt.Errorf("failed to fetch OIDC token: %w", err)
			}
			c.token = newToken
		}
		return c.token, nil
	}
```

If `var.product_id` contains a hyphen (e.g., `supercargo-web`), the MQL query will expand to `value.supercargo-web_validation_duration_ms`. In MQL, hyphens are treated as subtraction operators, which will cause a query syntax error. To prevent this, you should replace hyphens with underscores in the metric names and MQL queries.

```
    condition_monitoring_query_language {
      query    = <<-EOT
        fetch global
        | metric 'custom.googleapis.com/${replace(var.product_id, "-", "_")}_validation_duration_ms'
        | align delta(1m)
        | group_by [metric.product_id], 1m, [val: percentile(value.${replace(var.product_id, "-", "_")}_validation_duration_ms, 99)]
        | condition val > 100 'ms'
      EOT
      duration = "300s"
    }
```
